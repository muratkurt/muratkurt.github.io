shiv

An AI assistant that runs in your terminal, on the device.

Talk to a model, let it run commands, keep the conversation across sessions. Bring your own API key — the provider is up to you.

Since 2.0 it can also build tweaks, end to end, without leaving the phone.

Providers

Moonshot · DeepSeek · OpenAI · OpenRouter · Ollama (local) · custom endpoint

Anything speaking the OpenAI /chat/completions format works. Claude is reachable through OpenRouter — Anthropic's own API uses a different shape and isn't supported directly.

What it does

Reads and edits files, runs shell commands — with a permission prompt before anything that could change your device. Reading and listing don't ask.

Sessions are saved every turn. Continue with /continue, browse older ones with /resume, or rewind to an earlier point.

Background tasks — Ctrl+B sends a running job to the background. Press ↓ to reach the counter, Enter for detail, k to stop. Output streams while the job is still running.

Profiles keep several providers side by side. /profile picks who you connect to, /model picks what runs.

Commands

Turkish and English names both work, and a prefix is enough — /prof.

Writing tweaks

The bug that doesn't announce itself

Write a class name that doesn't exist and the code compiles. The tweak installs. It loads. And then nothing happens — no error, no log, no crash. You stare at working-looking code for hours.

This is the single most common way tweak work goes wrong, and it is why an AI writing tweak code is dangerous unless it can check its work.

So shiv reads your device

Every jailbroken iPhone already carries the shared cache — every system class, every method, sitting there in /System/Cryptexes. shiv parses it directly. No IPSW download, no Mac, no setup.

shiv-sinif LockScreen
shiv-sinif --metod SBLockScreenManager
shiv-sinif --metodara notificationCount

2190 classes scan in 28 ms. The model runs this itself before writing code, and if it can't confirm a name it says so instead of guessing.

App Store apps are encrypted

Their class names can't be read from disk — FairPlay encrypts the binary. shiv decrypts on the device, no Mac and no Python needed:

shiv-cek <bundle-id>

Measured: YouTube, 196 MB, 32,929 classes recovered.

What builds on the phone, and what doesn't

Most of it builds here. Tweaks targeting App Store apps and command-line tools compile, sign and install on the device — Theos, clang and ldid are all present.

System tweaks mostly work too. The exception is narrow but real: if your code hands a block to a system process, the on-device toolchain produces the wrong pointer-authentication ABI and the device drops into Safe Mode. Hooks, selector calls and ivar reads are fine; handing over a block is not.

shiv recognises that case, refuses, and explains why. With /mac it connects a Mac over SSH and builds there instead.

Start here

/ortam

Measures the whole development environment — jailbreak type, Theos path and flavour, SDKs, frida, and the build flow it recommends. Run it before anything else; it replaces guessing with measurement.

Good to know

Node.js is bundled. Install shiv and it runs — nothing else to add.

Don't run it as root. Files would end up owned by root and ~/.shiv could no longer be written by mobile.

Your data stays. Profiles, API keys, sessions and input history live in ~/.shiv. Removing the package leaves them alone — even on purge.

Your API key is yours. Stored locally, sent only to the provider you chose. /aktar exports a session with keys and device identifiers stripped.

BILGI.md — anything you put in ~/.shiv/BILGI.md is given to the model every session. Write down the quirks of your device once instead of explaining them every time.

Compatibility

Everything here was measured on one device: iPhone 15 Pro, iOS 17.0.3, RootHide. The rootless build has been verified on a rootless device; what is written about rootful rests on documentation, not testing.

Known limits. .appex extensions run in their own process and aren't decrypted by this route. Class lookup was verified on iOS 17 — on another version shiv says it can't confirm rather than returning a wrong name.

Changelog

2.0.0

shiv can now build tweaks end to end, on the device.

Tweak development

  • Class and method lookup — reads the device's own shared cache, and now also binaries outside it (Control Centre modules, Settings bundles, SDKs embedded in apps)
  • On-device decryption — shiv-cek <bundle-id> unwraps FairPlay without a Mac or Python; shiv-oku lists classes from a running app
  • /ortam — measures the development environment before work starts
  • Build guidance — the model knows which tweaks can be built on the phone and which need a Mac, and explains the difference instead of refusing flatly
  • TWEAK.md ships with the package: measured recipes the model reads when it needs them

Background tasks

  • Ctrl+B sends a running job to the background; ↓ reaches the counter, Enter opens detail, k stops it
  • Output streams while the job is still running, and the timer ticks every second

Fixed

  • Lines were losing their last character. The gutter mark ⎿ draws two columns in this terminal while shiv counted one, so every gutter line shifted a column and later redraws clipped the end. Now └.
  • Command tails (exit=1, elapsed time) overflowed the width budget
  • Ctrl+B was bound twice; the background branch was unreachable
  • Fold state is saved, so /resume no longer reopens collapsed text
  • Sessions broken by a half-finished tool call are repaired on load
  • Mac connection and respring now go through the permission prompt

Documentation — a standalone tweak development guide ships in belgeler/, readable on its own without shiv.
