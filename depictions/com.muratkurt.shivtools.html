shivtools

Tweak development tools that run on the iPhone itself. Measure the device instead of guessing — any CLI can drive them: Claude Code, Codex, Gemini, or you over SSH.

Highlights

  • Find the code to hook — classes, methods and real signatures from the running process
  • Read the screen — SpringBoard and app view trees as text
  • Measure, don't guess — a measurement log, screenshots as data, safe edits
  • Start from working code — a development guide and three example tweaks
  • Settings page — live status of the environment and every tool

Full walkthrough in the Usage tab and on GitHub.

Usage

With an AI agent

shivtools gives the AI you already run in the terminal (Claude Code, Codex, Gemini…) eyes and hands on the device.

mkdir -p ~/Documents/MyTweak && cd ~/Documents/MyTweak
shiv-kurulum

The rules file lands in the folder; the agent reads it when it starts there. With iOS MCP installed, shiv-mcp baglan prints the line that connects it.

No project folder? Tell the agent: shivtools is installed. Find the rules file with shiv-kurulum --goster, read it with cat, and follow it for this session. Then run shiv-ortam. (Say cat: on RootHide some agents' file tools can't see the jailbreak root.)

Then start the CLI in that folder and say what you want, for example:

  • Read CLAUDE.md, run shiv-ortam, and tell me what this device is ready for.
  • I want a SpringBoard tweak that hides the dock icon labels. Start from shiv-ornek 01 and measure before you change anything.
  • My tweak's Settings page is empty. Find out why — measure first, don't change code yet.

You respring, not the agent. After a RootHide re-jailbreak, run shiv-jbroot --yap before starting the CLI.

Start here

shiv-ortam

It prints the jailbreak type, iOS version, theos, SDK, frida, oldabi, node, the MCP server and every tool — and it runs each tool to check it, instead of only looking for the file. Run it first in every session; don't assume any of them.

shiv-ortam --ajan-sina checks the whole frida chain: client → server → attach → ObjC.

Set up a project

cd /var/mobile/Documents/MyTweak
shiv-kurulum

Writes CLAUDE.md and AGENTS.md from the bundled SHIVTOOLS.md — two names because different CLIs read different files. An existing copy is backed up with a timestamp first.

shiv-kurulum --fark shows how a project's copy differs from the installed one.

Start from an example

shiv-ornek                  # list
shiv-ornek 01 MyTweak       # SpringBoard hook
shiv-ornek 02 MyPrefs       # Settings page + tweak
shiv-ornek 03 MyAppTweak    # in-app network filter

Copies a working skeleton into a new folder and lists the names to change. It never writes over an existing folder. shiv-ornek --rehber prints where the guide is.

Find a class or a method

shiv-sinif SBMediaController
shiv-sinif --tara Inventory
shiv-sinif --metod SBMediaController
shiv-sinif --metod SBMediaController --tip
shiv-sinif --metod UIAction --tip --sdk --desen handler

--tip prints the type encoding — the return type and arguments — read from the live process. --sdk adds whether the selector is declared in the headers of that class, its superclasses or its protocols.

Default target is SpringBoard; --pid N or --bid <bundle-id> picks another process.

Read the screen

shiv-pencere
shiv-pencere --izle 60
shiv-ekran com.apple.Preferences --ac

shiv-pencere dumps SpringBoard: window levels, the view tree, frames, safe= insets, tf= transforms, EKRAN: where the screen disagrees with your model, and the interface orientation.

--izle SECS records: a new numbered dump each time the layout changes, with a vibration so you know a moment was captured. Use it with a short numbered script for the person holding the phone.

shiv-ekran does the same for the app in front (--ac brings it forward).

Measure behaviour

shiv-log parca        # C snippet to paste into the tweak
shiv-log yeni         # clear before a test round
shiv-log ozet         # count events
shiv-log son 60       # last lines

With iOS MCP installed, NSLog is readable live (get_syslog). Without it — or inside an app's sandbox — log to a file and summarise; reading the raw file costs the agent its context.

Screenshots as data

shiv-kare isaret      # remember the newest frame
shiv-kare yeni        # paths of frames taken after that

Visual faults — flicker, one-frame redraws, wrong placement — never show up in a log. Only frames after the mark are listed; the camera roll is personal.

Edit safely

shiv-sil Tweak.x 420 875 --kuru   # preview
shiv-sil Tweak.x 420 875

Dated backup, deletes only that range, verifies the new line count, prints the diff, then checks for broken comments and unbalanced braces. Exit code 2 means the delete happened but a check failed.

iOS MCP

The optional iOS MCP package lets an AI agent take screenshots, read the accessibility tree, tap, type and read the live system log.

shiv-mcp durum            # installed? running? which mode?
shiv-mcp baglan           # connect an agent on the phone
shiv-mcp baglan --mac     # SSH tunnel for an agent on a Mac

It listens on 127.0.0.1 only and mcp-root comes without setuid — both are settings. The server has no authentication: shiv-mcp mod ag asks before it listens on the network. From a Mac, prefer the SSH tunnel.

frida

The tools and the bundled client are built for frida 17 (arm64 + arm64e, measured on A12 and A17).

On RootHide, frida 17 can bring SpringBoard down on about the third attach in a row; apps are fine, and rootless is not affected. Batch SpringBoard work: read once with shiv-pencere or shiv-sinif --tip, then reuse the dump. shiv-ortam warns about it on RootHide.

Settings page

Settings → shivtools shows the last measurement: environment, every tool with a status mark, quick-start commands you can tap to copy, and credits. It reads what shiv-ortam measured — run shiv-ortam to refresh it.

Paths

  • Tools: /usr/local/bin/
  • Rules and recipes: /usr/local/share/shivtools/
  • Guide and examples: /usr/local/share/shivtools/rehber/, …/ornekler/
  • Output: /var/mobile/tw/

On RootHide the shell lives in jbroot while system processes use the real root. shiv-yol <path> translates between them.

If shiv is also installed

Both packages own the same /usr/local/bin/shiv-* names. Install shivtools after shiv; shiv-ortam and shiv-kurulum warn when the names point elsewhere.

Full guide

Everything above, and more, on GitHub. Report a problem with an issue — include your device, iOS, jailbreak and the output of shiv-ortam.
